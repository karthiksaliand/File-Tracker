**original_problem_statement**: The user wants to build a secure, role-based Government File Tracking Web Application.

**PRODUCT REQUIREMENTS**:
- **Objective**: A secure, role-based application for tracking government files.
- **Key Features**: Parallel departmental approvals, 30-day deadline monitoring, automatic recurring reminders, an escalation mechanism for delays, strict edit controls, a full audit trail, and complete visibility for higher authorities (ADC, DC).
- **User Roles**: Admin, Case Worker, 9 Tahsildar roles, Forest Officer, Superintendent of Police (SP), Assistant Commissioner (ADC), and Deputy Commissioner (DC).
- **Core Workflow**:
    1.  **Case Worker**: Creates a file with applicant details, a description, document uploads, and assigns it to a specific Tahsildar. The file is then sent simultaneously to the selected Tahsildar, Forest Dept, and SP Dept, starting a 30-day timer.
    2.  **Parallel Approval**: Tahsildar, SP, and Forest departments must approve/reject the file within 30 days. Their decisions are locked after submission.
    3.  **Reminders**: The system should send automatic notifications every 2 days to departments that haven't acted.
    4.  **Escalation**: If the 30-day deadline is missed, the file is marked Delayed, and an escalation notice is sent to Admin, ADC, and DC.
    5.  **Visibility**: ADC and DC have read-only access to all files and their statuses. The DC holds the final decision authority (Accept/Reject).
    6.  **Admin Authority**: The Admin has full control to view, edit, delete, override, and reassign any file. They also manage user credentials and view analytics and audit logs.

**User's preferred language**: English
